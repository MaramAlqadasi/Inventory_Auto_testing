# التنسيق بين الوكلاء (Orchestration) — تدفّق العمل والمخرجات

كل وكيل يستهلك مخرَج الذي قبله، ويُنتج "قطعة تسليم" (artifact) واضحة للذي بعده.
هذا الفصل هو ما يجعل الإطار قابلًا لإعادة الاستخدام: العقل ثابت، والقطع تنتقل بينها بشكل منظّم.

## التدفّق العام

```
project-context.md
        │
        ▼
┌─────────────────┐   test-plan.md        ┌──────────────────┐   *.spec.ts + POM   ┌────────────────┐
│   01-PLANNER     │ ───────────────────▶ │   02-GENERATOR    │ ──────────────────▶ │   03-HEALER     │
│ يحلّل ويخطّط      │   (خطة + جدول حالات   │ يحوّل الخطة إلى     │  (سكربتات Playwright)│ يشغّل ويُصلح     │
│                  │    + استراتيجية      │ كود Playflight     │                     │ الفشل/الهشاشة  │
└─────────────────┘    المُحدِّدات)        └──────────────────┘                     └────────────────┘
        ▲                                                                                    │
        └──────────────────── تغذية راجعة: مُحدِّدات/افتراضات تحتاج تصحيحًا ◀──────────────────┘
```

## قطع التسليم (Handoff Artifacts)

| من | إلى | الملف/القطعة | يحتوي على |
| :- | :-- | :----------- | :-------- |
| المستخدم | Planner | `project-context.md` | الرابط، الدخول، بنية الصفحة، قواعد العمل، بيانات الاختبار |
| Planner | Generator | `test-plan.md` | النطاق، تقييم المخاطر، جدول حالات الاختبار، بيانات الاختبار، **استراتيجية المُحدِّدات لكل عنصر**، مصفوفة التتبّع، الافتراضات |
| Generator | Healer | `tests/*.spec.ts` + `pages/*.ts` (POM) | سكربتات Playwright + كائنات الصفحات + ملف بيانات الاختبار |
| Healer | Planner/Generator | `healing-report.md` | المُحدِّدات التي فشلت + البديل المُستقر + افتراضات الخطة التي تبيّن خطؤها |

## مبادئ التسليم
1. **كل قطعة مكتفية بذاتها:** الـ Generator يجب أن يجد كل ما يلزمه في `test-plan.md` + `project-context.md` دون تخمين.
2. **المُحدِّدات تُقرَّر في الخطة لا في الكود:** البلانر يقترح استراتيجية المُحدِّد لكل عنصر، والمولّد ينفّذها — هذا يقلّل عمل المُصلِّح.
3. **حلقة تغذية راجعة:** عندما يصلح الـ Healer مُحدِّدًا، يكتبه في `healing-report.md` ليُحدَّث `project-context.md` (قسم المُحدِّدات) فلا يتكرّر الفشل.
4. **لا أفعال جانبية بلا إذن:** لا حذف بيانات حقيقية، لا تشغيل على بيئة إنتاج، فقط بيئة الاختبار المذكورة في السياق.
