# طبقة وكلاء اختبار الجودة (QA Agents) — تُبنى مرة، وتُعاد لكل مشروع

هذه الحزمة هي **"العقل" الثابت** لإطار الوكلاء الثلاثة (Planner → Generator → Healer).
تبنينها مرة واحدة وتعيدين استخدامها في أي مشروع جديد بمجرّد استبدال **ملف سياق المشروع** فقط.

```
qa-agents/                          ← الطبقة المشتركة (ثابتة — لا تتغيّر بين المشاريع)
├── README.md                       ← هذا الملف
├── orchestration.md                ← كيف يتسلّم الوكلاء العمل من بعضهم (تدفّق البيانات)
├── agents/
│   ├── 01-planner.md               ← برومبت البلانر (محايد للمشروع)
│   ├── 02-generator.md             ← برومبت المولّد (يحوّل الخطة إلى Playwright)
│   └── 03-healer.md                ← برومبت المُصلِّح (يعالج الاختبارات الفاشلة/الهشّة)
└── examples/
    └── smart-life-erp.context.md   ← مثال ملف سياق مُعبّأ لمشروعكِ

project-context.template.md         ← انسخيه لكل مشروع جديد واملئيه (هذا وحده ما يتغيّر)
```

## القاعدة الذهبية
**الوكلاء مرة واحدة، والسياق لكل مشروع.**
- ما يبقى ثابتًا: برومبتات الوكلاء + منطق التنسيق بينهم.
- ما يتغيّر فقط: رابط النظام، بيانات الدخول، بنية الصفحات، أسماء الأعمدة/الأزرار، استراتيجية المُحدِّدات، قواعد العمل، بيانات الاختبار → كلها في `project-context.md`.

## كيف تستخدمينها في مشروع جديد (3 خطوات)
1. **انسخي** مجلد `qa-agents/` كما هو إلى المشروع الجديد (أو اتركيه في مكان مركزي وأشيري إليه).
2. **انسخي** `project-context.template.md` داخل المشروع باسم `project-context.md` واملئي خاناته.
3. **شغّلي** كل وكيل بإعطائه برومبته + `project-context.md`. مخرَج كل وكيل يصبح مدخلًا للذي يليه (انظر `orchestration.md`).

## الإعداد لمرّة واحدة — تصفّح حيّ للبلانر (Claude Code + Playwright MCP)

يمنح هذا الإعداد البلانر القدرة على فتح النظام واستكشاف الصفحة فعليًا، مع جلسة دخول محفوظة فلا يُدخل كلمة المرور كل مرة. المتطلب الأساسي: **Node.js 20+**.

**1) أضيفي خادم Playwright MCP** (في الطرفية، خارج جلسة Claude Code):

```bash
claude mcp add playwright -- npx @playwright/mcp@latest \
  --caps=storage \
  --storage-state=./storage-state.json \
  --allowed-origins=https://smarterp.top
```
- `--` تفصل خيارات Claude عن أمر تشغيل Playwright.
- `--caps=storage` يفعّل أدوات حفظ/استرجاع الجلسة.
- `--allowed-origins` يحصر تصفّح الوكيل في نطاق نظامكِ فقط (حماية).
- النطاق الافتراضي **local** (خاص بكِ في هذا المشروع، يُخزَّن في `~/.claude.json` ولا يُشارَك) — وهو الأنسب لأن الجلسة سرّية. لمشاركة الإعداد مع الفريق استخدمي `--scope project` (يُكتب في `.mcp.json`)، مع إبقاء ملف الجلسة وكلمة المرور خارج المستودع.

**2) أعيدي تشغيل Claude Code وتحقّقي من الاتصال:**

```bash
claude mcp list          # يجب أن يظهر playwright
```
ومن داخل الجلسة: الأمر `/mcp` لإدارة الخوادم والتأكّد أن الحالة connected. (تغييرات الإعداد لا تسري حتى إعادة التشغيل.)

**3) سجّلي الدخول مرّة واحدة لحفظ الجلسة.** داخل جلسة Claude Code اطلبي:
> «افتح صفحة دخول النظام، أدخل المستخدم والمرور من `project-context.md`، اضغط دخول، ثم احفظ حالة الجلسة في `storage-state.json`».

بعدها يستعيد الخادم الكوكيز تلقائيًا في كل تشغيل، فينتقل البلانر إلى الصفحة المستهدفة مباشرةً.

**4) خطوة الاستكشاف في برومبت البلانر** تصبح: «انتقل إلى مسار الصفحة من السياق؛ إن أُعِدتَ لصفحة الدخول فالجلسة انتهت — أبلِغ المستخدم لإعادة توليد `storage-state.json`».

🔒 **أمان:** أضيفي `storage-state.json` إلى `.gitignore` (يحوي جلسة فعّالة)، ولا تودعي كلمة المرور في أي ملف يُرفع للمستودع — يُفضَّل ملف `.env` غير متتبَّع.

> بديل موفّر للتكلفة: أصدرت Microsoft `@playwright/cli` باستهلاك توكنز أقل بنحو 4 أضعاف من MCP، ويناسب الوكلاء الذين يملكون وصولًا لنظام الملفات مثل Claude Code — جرّبيه لاحقًا إن صارت تكلفة الجلسات مرتفعة.

## الترقية بدون ألم
أي تحسين تجرينه على برومبت أحد الوكلاء، أجريه في `qa-agents/` المركزية فقط، فيستفيد منه كل المشاريع.
لو نسختِ المجلد لكل مشروع، فالتحسين يتطلّب تحديث النسخ يدويًا — لذا يُفضَّل إبقاء `qa-agents/` في مكان مركزي واحد.
